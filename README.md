# MediaLib

A **local-first personal media library** that unifies books, comics, manga,
anime, movies, TV, games, and music in a single application. The library lives
on your own device in a local SQLite database; the network is only used to
*enrich* entries with metadata, never to store them.

> Final Year Project — Local-First Personal Media Library.
> See [`PROJECT_PROPOSAL.md`](../PROJECT_PROPOSAL.md) and the thesis in
> [`medialib-fyp-thesis`](../medialib-fyp-thesis) for the full specification.

## Features

- **One library, every medium.** A unified catalogue with per-type fields
  (pages, chapters, episodes, runtime, tracks, platform, ISBN).
- **Local-first & offline.** Built on SQLite via [Drift]; the app is fully
  usable without a connection.
- **Entry management.** Create, edit, filter, and delete entries; track
  status, progress, ratings, and notes. Status/progress changes are recorded in
  a consumption history timeline.
- **Metadata enrichment.** Fetch covers, descriptions, creators, release dates,
  ratings, and counts from external services, with results cached locally:
  - [AniList] — anime & manga (keyless)
  - [Open Library] — books (keyless)
  - [MusicBrainz] — music (keyless)
  - [TMDB] — movies & TV (API key, set in Settings)
- **Data portability.** Export the whole library to an open JSON document and
  import it back (merge or replace).
- **Cross-platform.** Windows, Linux, and Android are the primary targets;
  iOS and macOS should work from the same codebase.

## Getting started

**Requirements:** Flutter 3.x (stable) with the platform toolchain for your
target (Linux desktop, Windows desktop, or Android SDK).

```bash
flutter pub get

# Run on a desktop target
flutter run -d linux     # or: flutter run -d windows

# Run on a connected Android device/emulator
flutter run -d android
```

### Code generation

The database layer is generated by Drift. After changing anything under
`lib/core/database/`, regenerate:

```bash
dart run build_runner build
```

## Quality checks

```bash
dart format lib test        # format
flutter analyze             # static analysis
flutter test                # unit + widget tests
```

## Building

```bash
flutter build linux   --release
flutter build windows --release
flutter build apk     --release
```

CI runs analysis, tests, and release builds for Linux, Windows, and Android on
every push (see `.github/workflows/ci.yml`). Tagging a commit `v*` builds and
attaches release artifacts (see `.github/workflows/release.yml`).

## Privacy & data ownership

The primary copy of your library is a SQLite database on your device. External
metadata services are optional and only contacted when you ask for enrichment;
failed requests never block the app, and previously cached values remain
available offline. Export produces a documented, human-readable JSON file so
your data is never locked in.

## Project structure

```
lib/
├── main.dart                 # entry point (ProviderScope)
├── app.dart                  # MaterialApp.router + Forui theme
├── core/
│   ├── database/             # Drift tables, DAOs, database, providers
│   ├── repositories/         # domain-level data access
│   ├── router/               # go_router config + navigation model
│   ├── settings/             # app settings keys + providers
│   ├── theme/                # Forui theme + persisted theme mode
│   └── widgets/              # shared widgets (dialogs, icons, placeholders)
└── features/
    ├── shell/                # responsive navigation shell
    ├── library/              # library list/grid + entry editor
    ├── history/              # consumption timeline
    ├── metadata/             # providers, service, search dialog
    ├── settings/             # settings screen
    └── transfer/             # JSON import/export
```
